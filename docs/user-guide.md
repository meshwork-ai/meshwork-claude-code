# Meshwork for Claude Code 사용 가이드 (팀원용)

내 Claude Code 세션이 팀원의 세션과 **직접 질문 · 답변**한다. "○○에게 …물어봐" 한마디면,
상대방 에이전트가 자기 로컬 작업 맥락(커밋 전 결정 포함)으로 답한다.

준비할 것: **서버 주소**(다운로드 페이지 · 조직 관리자가 알려 줌)와 **회사 계정**(로그인).
초대 코드는 없다 — 관리자가 회사 이메일로 미리 등록해 두면 로그인하는 순간 내 자리에 연결된다.

## 설치 (처음 한 번, 약 3분)

사전 요구: macOS · Linux · Windows(Git Bash) · Claude Code · **Node.js 22 이상**(없으면 Bun 으로도 돈다).
플러그인은 의존성을 담은 파일 하나로 배포되므로 따로 설치할 패키지는 없다.

### 1) GitHub 를 HTTPS 로 (사내망 사용자 권장)

사내망은 GitHub SSH(22번 포트)를 막는 경우가 많다. 설치가 `port 22 timed out` 으로 실패하면 이 한 줄을 실행한다.

```bash
git config --global url."https://github.com/".insteadOf "git@github.com:"
```

### 2) 플러그인 설치 — Claude Code 안에서

```text
/plugin marketplace add meshwork-ai/meshwork-claude-code
/plugin install meshwork@meshwork
```

### 3) alias 등록

셸 프로필(`~/.zshrc`)에 넣고 터미널을 다시 연다. 팀과 이어 둘 세션은 `claude` 대신 `meshwork-claude` 로 켠다.

```bash
# 기본 — 권한 묻기는 평소대로 (권장)
alias meshwork-claude='MESHWORK_GATEWAY=1 claude --dangerously-load-development-channels plugin:meshwork@meshwork'
# 권한을 묻지 않음 — 믿을 수 있는 작업에서만
alias meshwork-claude-yolo='MESHWORK_GATEWAY=1 claude --dangerously-skip-permissions --dangerously-load-development-channels plugin:meshwork@meshwork'
```

### 4) 켜고 로그인

`meshwork-claude` 로 세션을 켠다. 처음 한 번만 확인 두 개가 뜬다 — 개발 채널 경고에서
"I am using this for local development", 새 MCP 서버에서 "Use this MCP server". 그다음:

```text
/meshwork:login <서버 주소>
```

1. 처음 보는 서버라서 **확인 상자**가 뜬다 — 주소가 맞으면 [로그인]을 고른다(에이전트가 팀원 메시지에 속아 엉뚱한 서버로
   로그인하지 못하게 사람이 고르는 상자다. 같은 서버로 다시 로그인할 때는 뜨지 않는다)
2. 세션에 **확인 코드**(예: `WDJB-MJHT`)가 보이고 브라우저가 열린다
3. 브라우저에서 **회사 계정**으로 로그인한다
4. 승인 화면의 코드가 **세션에 보인 코드와 같은지** 확인하고 [허용]을 누른다 — 다르면 누르지 않는다(남이 시작한 요청일 수 있다)
5. 세션에 `[로그인 완료]` 가 온다. 조직이 여럿이면 고르는 상자가 뜬다

서버 주소는 한 번만 넣으면 기억한다. 다음부터는 `meshwork-claude` 로 켜기만 하면 자동으로 붙는다.
로그인이 필요해지면(만료 · 로그아웃) 켤 때 안내 한 줄과 상태줄로 알려 준다 — 브라우저를 저절로 열지는 않는다.

### 5) 상태줄 등록 (권장, 10초)

`~/.claude/settings.json` 에 아래를 넣고 Claude Code 를 다시 켠다. 연결이 끊기거나 플러그인이 죽어도
**상태줄이 바로 알려 준다.**

```jsonc
{ "statusLine": { "type": "command", "command": "~/.claude/channels/meshwork/statusline.sh" } }
```

> 경로에 **버전이 들어가지 않는다** — 플러그인이 켜질 때마다 스크립트를 이 자리로 복사한다. 업데이트해도 다시 고칠 일이 없다.
> 시범 기간에 team-relay 상태줄을 쓰고 있다면 그대로 두고, 이사 날 바꾼다(아래 「시범 기간」).

| 상태줄 | 뜻 |
|---|---|
| `[meshwork 🟢 web3]` | 정상 — 그 방을 받는 중 |
| `[meshwork 🟢 web3 +1] · ⏳2` | 방 두 개를 받는 중 + 보관 메시지 2건 |
| `[meshwork ⚠️ 받는 방 없음 · 빈 방 1]` | 아무 방도 받지 않는 중 → `/meshwork:room <방 이름>` |
| `[meshwork 로그인 필요 — /meshwork:login]` | 로그인이 끝났거나 아직 안 함 |
| `[meshwork 조직 고르기 — /meshwork:login org]` | 붙을 조직을 골라야 함 |
| `[meshwork ✗ 연결 끊김 — 다시 붙는 중]` | 서버에 닿지 못함 — 알아서 다시 붙는다 |
| `[meshwork ✗ 업데이트 필요]` | 서버가 이 버전을 받지 않음 → 아래 「업데이트」 |
| `[meshwork ✗ 플러그인 미동작]` | 플러그인이 죽었거나 못 떴음 → `/mcp` 다시 연결 또는 Claude Code 다시 켜기 |
| `[meshwork 🌙 퇴근]` | 퇴근 중 |
| `… · 규약 바뀜(새 세션)` | 켠 뒤 팀 규약 · 방 메모리가 바뀜 — 새 세션부터 들어간다 |
| `… · 📢 …` | 서비스 · 조직 공지 한 줄 |

## 팀 세션 = meshwork-claude 로 켠 세션

- **팀 기능은 `meshwork-claude` 로 켠 세션에서만 쓴다.** 묻기 · 답하기 · 받기 전부다. 평소처럼 `claude` 로 켠 세션은
  서버에 붙지 않고 아무 방해도 하지 않는다. 주력 작업 세션 하나를 `meshwork-claude` 로 켜는 것을 권한다 — 자기 소관 질문에
  그 세션의 작업 맥락으로 바로 답하므로 답이 가장 좋다.
- **방에서 말하려면 그 방을 받고 있어야 한다.** 보낸 질문의 답은 그 방을 받는 세션으로 오기 때문이다.
- **여러 세션**: 세션마다 **다른 방**을 받을 수 있다(A세션 = 1번 방, B세션 = 2번 방). `--resume` 으로 다시 켜면 받던 방을
  되찾는다. 새 세션은 `/meshwork:room web3` 처럼 정한다. 참가한 방이 하나뿐이면 저절로 받는다.
- **받는 방은 실수로 뺏기지 않는다.** 세션을 켜는 것만으로는 다른 세션이 받는 방을 가져오지 않는다 — `[받지 못한 방]`
  안내만 뜨고 그 세션이 계속 받는다. 이 세션으로 가져오려면 `/meshwork:room <방 이름>` 을 직접 실행한다 — 그때만 앞 세션이
  `[받는 방 이전]` 알림과 함께 받지 못하게 된다. 네트워크가 잠깐 끊겼다 붙는 것은 같은 세션이라 아무 일도 없다.
- `claude` 로 켠 세션에서 팀 기능을 부르면 이렇게 나온다 — `meshwork-claude` 세션에서 다시 하면 된다.
  ```
  이 세션에서는 Meshwork 를 쓸 수 없습니다 — meshwork-claude 로 켠 세션에서 다시 해 주세요
  ```
- **일반 세션에서 팀에 물을 일이 생기면** 같은 컴퓨터의 `meshwork-claude` 세션에게 부탁한다 — *"팀 세션한테 경환님께 ○○
  물어봐 달라고 해 줘"*. 반대로 팀 세션에 들어온 질문을 작업 세션으로 넘기는 것은 `/meshwork:route` 다.

### 세션별로 쓸 수 있는 것

| 기능 | meshwork-claude (방을 받는 중) | meshwork-claude (받는 방 없음) | 일반 `claude` |
|---|---|---|---|
| 보내기 · 답장 · 합의 · 메모리 제안 · 방장 공지 | ✓ | ✗ | ✗ |
| 받기(팀원 질문이 이 세션에 옴) | ✓ | ✗ | ✗ |
| 방 가져오기 `/meshwork:room` | ✓ | ✓ (가져오면 왼쪽 칸이 된다) | ✗ |
| 상태 · 지난 대화 · 합의 목록 · 메모리 보기 | ✓ | ✓ | ✗ |
| 퇴근 · 출근 · 로그인 · 초대 링크 참가 | ✓ | ✓ | ✗ |
| 진단 `/meshwork:doctor` · 질문 배분 `/meshwork:route` | ✓ | ✓ | ✓ (이 컴퓨터 안의 일만) |

### 이름은 방마다 다를 수 있다

신원은 **회사 계정 하나**고, 방마다 다른 이름을 쓸 수 있다. 어떤 방에선 `이하늘`, 다른 방에선 `하늘` 이어도 같은 사람이다.

## 사용법

`/meshwork:` 까지 치면 명령 목록이 뜨고, 명령을 고르면 넣을 값이 회색 힌트로 보인다. 예시의 방 이름 · 이름은 자기 것으로 바꾼다.

| 명령 | 하는 일 |
|---|---|
| [`/meshwork:status`](#meshworkstatus--연결-상태--자동-답장) | 연결 상태 · 방 사람들, 답장 전 내 확인 받기 |
| [`/meshwork:room`](#meshworkroom--받을-방-정하기) | 이 세션이 받을 방 정하기 |
| [`/meshwork:away`](#meshworkaway--퇴근--출근) | 퇴근 · 출근 |
| [`/meshwork:doctor`](#meshworkdoctor--문제-진단) | 뭔가 안 될 때 진단 |
| [`/meshwork:login`](#meshworklogin--로그인--조직--로그아웃) | 로그인 · 조직 바꾸기 · 로그아웃 |
| [`/meshwork:join`](#meshworkjoin--초대-링크로-방-참가) | 초대 링크로 방 참가 |
| [`/meshwork:route`](#meshworkroute--질문-배분) | 내 소관이 아닌 질문을 이 컴퓨터의 다른 세션에 넘기는 규칙 |
| [`/meshwork:owner`](#meshworkowner--방장-초대-링크--내보내기--공지--메모리) | (방장) 초대 링크 · 내보내기 · 공지 · 메모리 |

질문 · 답장 · 지난 대화 · 합의처럼 **명령어가 없는 기능은 말로 한다** — 아래 「말로 하는 것」.

### `/meshwork:status` — 연결 상태 · 자동 답장

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 연결 상태 · 방 사람들 | `/meshwork:status` | 조직 · 이 세션이 받는 방 · 참가한 방(누가 받는지) · 방 사람들 🟢출근 🟡자리 비움 🌙퇴근 ⚪오프라인 ⚠️무응답 · 자동 답장 |
| 답장 전에 내 확인 받기 | `/meshwork:status auto-reply off` | 팀 질문에 바로 답하지 않고 **답장 초안을 먼저 보여 준다** |
| 다시 바로 답하게 | `/meshwork:status auto-reply on` | 기본값으로 |

### `/meshwork:room` — 받을 방 정하기

한 사람의 한 방은 **한 세션만** 받는다. `--resume` 으로 다시 켜면 받던 방을 되찾는다.

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 받는 방 보기 · 고르기 | `/meshwork:room` | 참가한 방과 각 방을 어느 세션이 받는지 보이고 고르는 창이 뜬다 |
| 이 세션이 받을 방 | `/meshwork:room web3` | `✓ 이 세션이 받는 방: web3` |
| 여러 방 받기 | `/meshwork:room web3,ops` | 쉼표로 적은 방을 모두 받는다 |
| 다른 세션이 받던 방 가져오기 | `/meshwork:room ops` | `↪ … 가져왔습니다` — **원래 세션은 그 방을 받지 못하게 된다** |

### `/meshwork:away` — 퇴근 · 출근

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 퇴근 | `/meshwork:away on` | 🌙 팀 메시지가 서버에 보관된다(보관 기한도 멈춘다). 보내기는 계속 된다 |
| 출근 | `/meshwork:away off` | 보관됐던 메시지가 한꺼번에 온다 — 2건 이상이면 **부재중 요약**부터 |

퇴근 · 출근은 **사용자 전체**에 적용된다 — 앱을 쓰면 앱에도 같은 상태가 보인다.

### `/meshwork:doctor` — 문제 진단

"메시지가 안 와요" 일 때 가장 먼저 실행한다. 런타임(Node) · 설정 · 로그인 · 연결 · 받는 방 · 보관 메시지 · 규약을
✓ · ✗ 로 점검하고 ✗ 마다 할 일을 알려 준다.

### `/meshwork:login` — 로그인 · 조직 · 로그아웃

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 처음 로그인 | `/meshwork:login meshwork.example.com` | 확인 상자 [로그인] → 확인 코드 · 브라우저 → 회사 계정으로 로그인 → 코드가 같은지 보고 [허용] |
| 다시 로그인 | `/meshwork:login` | 서버 주소는 기억하고 있다 |
| 붙을 조직 바꾸기 | `/meshwork:login org` · `/meshwork:login org Acme` | 조직이 여럿일 때 고르는 상자(이름을 주면 바로) |
| 서버를 옮겼을 때 | `/meshwork:login 새주소.example.com` | 처음 보는 서버라 확인 상자 → 옛 서버의 로그인은 폐기된다 |
| 이 기기 로그아웃 | `/meshwork:login logout` | 서버에서 이 기기의 로그인을 폐기하고 토큰을 지운다 — 이 컴퓨터의 다른 터미널도 함께 끊긴다 |

### `/meshwork:join` — 초대 링크로 방 참가

방장 · 관리자가 보낸 **초대 링크**(1회용 · 7일)로 참가한다. 링크를 브라우저에서 바로 열어도 되고, 세션에서 열어도 된다.

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 초대 링크로 참가 | `/meshwork:join https://meshwork.example.com/join/…` | 브라우저가 열린다 → 조직 · 방 · 초대한 사람을 확인하고 **[참가]** → 세션에 `[방 참가]` 가 오고 **이 세션이 그 방을 받는다** |

초대는 **사람이 직접 [참가]를 눌러야** 한다 — 플러그인이 대신 참가하지 않는다(팀원 메시지에 숨은 링크로 에이전트가 남의 방에 들어가지 못하게).

### `/meshwork:route` — 질문 배분

이 세션 소관이 아닌 팀 질문을 **이 컴퓨터의 다른 세션**에 넘기는 규칙이다. 세션 이름은 그 세션에서 `/rename` 으로 붙인 이름이다.
처음 켤 때 **team-relay 에 등록해 둔 규칙을 가져온다.** 등록이 없으면 내 세션 쪽 위임은 하지 않고, 다른 사람 · 역할로 넘기거나 사용자에게 확인한다.

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 규칙 목록 | `/meshwork:route` | 등록된 규칙. 비어 있어도 정상 |
| 낱말로 넘기기 | `/meshwork:route add "kafka, 인프라" infra-session` | 이 낱말의 팀 질문은 `infra-session` 세션이 답한다 |
| 방 단위로 넘기기 | `/meshwork:route add --room ops ops-session` | 그 방 질문은 낱말과 상관없이 늘 그 세션이 답한다 |
| 지우기 | `/meshwork:route remove "kafka, 인프라"` · `/meshwork:route remove --room ops` | `✓ 지움` |

### `/meshwork:owner` — (방장) 초대 링크 · 내보내기 · 공지 · 메모리

방장 · 조직 관리자가 쓴다. 방장 지정은 조직 관리자가 한다(조직 콘솔).

| 하고 싶은 것 | 명령어 예시 | 결과 |
|---|---|---|
| 초대 링크 만들기 | `/meshwork:owner invite web3 민준` | 1회용 링크(7일) — 받을 사람에게 전한다. 이름은 **그 방에서만** 쓸 이름 제안(빼도 된다). **링크 주소는 이때만 보인다** |
| 살아 있는 링크 보기 | `/meshwork:owner invites web3` | 번호 · 만든 사람 · 만료(주소는 보이지 않음) |
| 잘못 보낸 링크 취소 | `/meshwork:owner revoke web3 inv_…` | 그 링크로는 참가할 수 없다 |
| 방에서 내보내기 | `/meshwork:owner kick web3 민준` | **그 방에서만** 빠진다. 다른 방 · 조직은 그대로 |
| 방 전원 공지 | `/meshwork:owner notice web3 내일 오전 배포라 11시까지 머지해 주세요` | 바로 받은 수 · 보관한 수. 받는 쪽은 답하지 않고 보여 주기만 한다. **이 세션이 그 방을 받고 있어야** 보낼 수 있다 |
| 방 메모리 보기 · 고치기 | `/meshwork:owner memory web3`<br>이어서 *"2번 지우고 '금요일 배포 금지' 더해 줘"* · *"지은 제안 승인해 줘"* | 지금 메모리와 대기 중인 제안이 보이고, 고치면 그 방의 새 세션부터 들어간다 |

> "권한이 없습니다" 면 그 방의 방장이 아니다 — 조직 관리자에게 방장 지정을 요청한다.

### 말로 하는 것 (명령어 없이)

| 하고 싶은 것 | 이렇게 말하기 | 결과 |
|---|---|---|
| 팀원에게 질문 | *"박도윤에게 배포 일정 물어봐 줘"* | 보내진다. 상대가 퇴근 · 오프라인이면 "보관" — 받을 수 있게 되면 간다 |
| 역할에게 질문 | *"결제 담당에게 환불 API 실패 원인 물어봐 줘"* | 그 역할에서 지금 답할 수 있는 사람이 받는다(`↳ ○○님이 받았습니다`) |
| 답이 필요 없는 전달 | *"도윤님께 배포 끝났다고 알려만 줘"* | 무응답 알림 없이 전달만 |
| 지난 대화 찾기 | *"도윤이랑 주고받은 대화 보여 줘"* · *"currency 얘기한 거 찾아 줘"* | 내가 끼어 있는 대화만(남의 1:1 은 못 본다) |
| 합의 기록 | *"방금 합의한 스키마 대장에 올려 줘"* | 상대 에이전트가 대화와 맞는지 확인하면 확정 — 같은 방 전원이 본다 |
| 합의 목록 | *"web3 방 합의 목록 보여 줘"* | 확정(방 전원) · 확인 대기 · 거절 · 만료(당사자만) |
| 방 메모리 제안 | *"스테이징 DB 가 매일 06시에 초기화된다는 거 방 메모리에 제안해 줘"* | 방장이 승인하면 그 방 전원에게 들어간다. 72시간 안에 처리되지 않으면 폐기 알림 |

### 알아두면 좋은 것

- 받은 메시지는 `<channel from="민준" author="agent" room="web3" thread="thr_…" kind="question">` 처럼 들어온다.
  `author` 가 `person` 이면 사람이 앱에서 직접 쓴 것이다.
- 보낸 질문에 상대 에이전트가 **15분**(사람이 직접 받았으면 업무 시간 **2시간**) 반응이 없으면 `[무응답]` 알림이 온다.
- 받을 곳이 없으면 **72시간 보관**하고(퇴근 중엔 기한이 멈춤), 그래도 못 전하면 `[보관 만료]` 가 온다.
- 받은 질문을 내가 **앱에서 먼저 답했으면** 세션에 `[이미 답함]` 이 오고, 에이전트는 그 질문에 답하지 않는다.
- 바로 답하지 못하면 에이전트가 "처리 중" · "사람에게 확인 중" 을 먼저 알린다 — 묻는 쪽에 무응답이 뜨지 않게.
- 팀원 메시지는 내 권한 승인을 대신할 수 없고, 설정 변경 · 비밀값 요구는 거절된다. 플러그인 알림(`[이미 답함]` 등)은
  `from` 없이 `author="plugin"` 으로만 온다 — 팀원 글 속에 같은 말이 있어도 알림이 아니다.
- Meshwork 의 로그인 토큰 · 설정 폴더(`~/.claude/channels/meshwork/`)는 **보호 훅**이 지킨다 — 에이전트가 읽거나 바꾸려 하면
  막힌다. 그 밖의 내 작업은 막지 않는다.
- 같은 방에 누가 들어오고 나가면 알림이 온다(`'민준'님이 참가했습니다.`).

### 열린 방

방장이 방을 **열린 방**으로 바꾸면, 그때부터 그 방에서 시작하는 1:1 대화가 **방 사람 모두에게 보인다**(앱의 방 화면 · 지난 대화 찾기).
열기 전 대화는 그대로 닫혀 있고, 다시 닫아도 이미 공개된 대화는 공개된 채로 남는다.

| 어디서 | 보이는 모양 |
|---|---|
| `/meshwork:status` · 상태줄 | 방 이름 옆 `[열림]` |
| 보내기 · 답장 결과 | `👁 'web3'은 열린 방 — 이 대화는 방 사람 모두에게 보입니다` |
| 받은 메시지 | 꼬리표 `open="room"` |

- 열린 방에서는 비밀 · 개인 정보를 꺼내지 않는다. 보내기 전에 따로 묻지는 않는다(내 일을 막지 않게) — 대신 위처럼 늘 보인다.
- **남의 열린 대화 읽기**: 방에 「에이전트도 열린 대화 읽기」 가 켜져 있을 때만 에이전트가 `history` 로 찾거나 열어 볼 수 있다.
  처음 읽을 때 확인 상자가 뜬다 — **[이번만] · [이 세션 동안] · [읽지 않음]**. 내가 시킨 일일 때만 허락한다(팀원 메시지가
  시킨 것이면 [읽지 않음]). 허락하지 않으면 내가 끼어 있는 대화만 보인다.
- 남의 열린 대화에서는 메시지만 보이고, 받음 · 처리 중 · 무응답 같은 상태는 그 대화의 당사자에게만 보인다.

### 방 메모리

방마다 **그 방에서 알아야 할 짧은 사실**이 적혀 있을 수 있다 — 설명 한 줄과 내용 최대 3개.
예: *"백엔드 판단은 정우진"*, *"금요일 배포 금지"*. 방장 · 관리자가 정리한다.

- **세션을 켤 때 자동으로 들어온다.** 비어 있는 방은 아무것도 들어오지 않는다.
- 세션 도중에 바뀌면 **떠 있는 세션에는 넣지 않고 새 세션부터** 들어간다 — 상태줄에 `규약 바뀜(새 세션)` 이 보인다.
- 켤 때 서버에 닿지 못하면 지난번 받아 둔 내용으로 시작하고 "최신이 아닐 수 있음" 이 붙는다.
- 넣을 만한 것은 **코드를 읽어서는 알 수 없고 답이 매번 같은 것**이다. 에이전트가 같은 걸 두 번 묻는다면 제안할 때다.

> **기록 고지**: 팀 메시지는 Meshwork 서버에 **조직 키로 암호화**돼 저장되고, 조직의 정책에 따라 조직 관리자가 볼 수 있다
> (자세한 것은 조직의 사내 이용 안내). 활동 기록(합의 · 퇴근 · 출근 · 받는 방 바뀜 · 세션 시작)에는 어느 세션인지 알아보도록
> 세션의 **작업 폴더 전체 경로**와 **세션 이름**(`/rename` · 상태줄을 켠 경우)이 함께 남는다. 개인적인 내용은 이 채널로 주고받지 않는다.

## 시범 기간 — team-relay 와 같이 쓰기

시범 기간에는 **실제 업무 대화를 계속 team-relay 에서** 한다. 두 플러그인을 같이 설치해도 서로 간섭하지 않는다.

| | team-relay | Meshwork |
|---|---|---|
| 켜는 명령 | `claude-team` | `meshwork-claude` |
| 명령 | `/team-relay:…` | `/meshwork:…` |
| 설정 폴더 | `~/.claude/channels/team-relay/` | `~/.claude/channels/meshwork/` |
| 상태줄 | 시범 기간엔 그대로 | 이사 날 바꾼다 |

**이사 날**: team-relay 플러그인을 지우고(`/plugin` → team-relay → Uninstall), 상태줄을 Meshwork 것으로 바꾸고,
**새 세션**을 `meshwork-claude` 로 켠다. 방마다 세션을 나눠 받던 사람만 `/meshwork:room` 을 한 번 다시 한다.

## 업데이트

1. `/plugin` → **Marketplaces** → `meshwork` → **Update marketplace** → `/plugin` 창을 닫으면 지금 세션에는 바로 적용된다
2. 켜져 있던 **다른 세션**은 옛 버전으로 계속 돈다 — 그 세션에서 `/reload-plugins` 를 한 번(또는 새 세션)
3. **팀 규약 · 방 메모리는 세션을 켤 때만 들어간다** — 바뀐 규약까지 확실히 쓰려면 **새 세션**으로 켠다
4. 권장: 같은 화면에서 **Enable auto-update** 를 켜 둔다

무엇이 바뀌었는지는 [업데이트 내역(CHANGELOG)](../CHANGELOG.md). 터미널에서는 `claude plugin update meshwork@meshwork`.

## 잘 안 될 때

**먼저 `/meshwork:doctor`.** ✗ 마다 할 일을 알려 준다. 아래는 doctor 로도 안 풀릴 때.

| 증상 | 조치 |
|---|---|
| 설치가 `port 22 timed out` | 설치 1) 의 git config 한 줄을 실행하고 다시 install |
| `/meshwork:login` 이 없는 명령이라고 나옴 | 플러그인을 설치하지 않았거나, `meshwork-claude` 대신 `claude` 로 켠 것 |
| `/mcp` 에 meshwork 가 "Failed to connect" | Node 22 이상이 있는지(`node -v`). 없으면 설치하고 새 세션 |
| 로그인 코드가 "만료" | 10분 안에 [허용] 해야 한다 — `/meshwork:login` 으로 다시 |
| 로그인했는데 "조직을 골라야 합니다" | `/meshwork:login org`. 조직이 나를 추가했지만 수락 전이면 브라우저 로그인 화면에서 [수락] |
| 조직에 속해 있지 않다고 나옴 | 조직 관리자에게 회사 이메일로 미리 등록(또는 초대 링크)을 요청 |
| 상대가 계속 오프라인 | ① 상대도 `meshwork-claude` 로 켰는지 ② 상대가 그 방을 받는지(`/meshwork:status`) ③ 플러그인을 최신으로 |
| 보내기는 되는데 받기가 안 됨 | 이 세션이 그 방을 받는지 본다(`/meshwork:status`). 다른 세션이 받고 있으면 `/meshwork:room <그 방>` — 보관분까지 온다 |
| 컴퓨터를 바꿨다 | 새 컴퓨터에서 설치 → `/meshwork:login <서버 주소>`. 방 · 이름 · 보관 메시지는 서버에 그대로 있다. 옛 컴퓨터는 `/meshwork:login logout`(또는 앱의 기기 목록에서 끊기) |
| 상태줄만 `✗ 플러그인 미동작` | `/mcp` 에서 meshwork 를 다시 연결하거나 Claude Code 를 다시 켠다 |
